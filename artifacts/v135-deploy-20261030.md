## 3. 线上复跑（`live_replay_short.py`）——被外部模型后端阻断，非本次代码问题

脚本流程走到建会话 + 上传附件 + 发起流式问答后，**第一轮 LLM 调用即失败**：

```
HTTP=200
event: phase {"phase":"thinking","round":0,"budget":800}
event: error ChatProviderAuthError: 模型接入点拒绝了这次请求（API key 无效或已过期）…
  KernelError: LLM 拒绝了请求（HTTP 403）：{"error":{"message":"No permission to access group vip (request id: 202610301424065028362868268d9d6XzJdVgGd)"}}
DONE elapsed=0.3s
```

直接探测生产的两个接入点（`app.providers.service.verify_provider`，密钥不出库）：

| label | model | base_url | is_default | 结果 |
|---|---|---|---|---|
| deepseek-v4.1-flash | deepseek-v4.1-flash | http://10.39.200.13/v1 | True | ❌ HTTP 403 `No permission to access group vip` |
| qwen | qwen3.8-27b-fp8 | http://10.39.16.9/v1 | False | ❌ HTTP 502（对方服务异常） |

结论：默认接入点的 key 已无 vip 组权限（403），备用 qwen 端点 502。**两个模型后端都不可用**，
与本次 chat-stop 修复无关（修复只动 chat 收尾/接手/工具调用解析，未触及 provider/LLM 配置）。
因此「线上整轮跑通并给出完整结论」这一条无法在当前基础设施下完成。

### 解除阻断后如何复跑

1. 到「设置 → 模型」更新默认接入点（deepseek-v4.1-flash）的密钥使其恢复 vip 权限，或修复 qwen 端点 502；
2. 在生产执行：`sudo /root/suvex/suvex-api/.venv/bin/python3 /home/kali/live_replay_short.py`（脚本已上传至 Kali）；
3. 判据：最后出现唯一 `surface: answer` 的完整结论（偏移/gadget/libc 线索），且该轮 `turn_runs.status` 不是未答完却记 `done`。
