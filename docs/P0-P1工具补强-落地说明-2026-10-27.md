## 2. 为什么是这些（缺口依据）

`_tmp/gap_probe.sh` 在两个镜像（base / re）里逐条 `command -v`，结论：

- **APK 题连壳都打不开**：三镜像全缺 jadx / apktool / dex2jar。平台只有 2 个 `.apk` 附件，但「reverse 题里出现 APK」是常见形态，缺了就整类做不了。
- **RSA 只能手搓**：没有 `RsaCtfTool`，小指数 / 共模 / Wiener / 费马分解这些全得模型自己写脚本，慢且易错。
- **音视频隐写缺 ffmpeg**：频谱图、抽音轨做不了（`view_image` 已经能看图，缺的是取图那一步）。
- **造包/改包缺 scapy**：pcap 类 Misc 题只能靠 `pcapfix` 修，不能按字段构造。
- **Pwn 缺 gef / one_gadget / seccomp-tools**：堆题调不动、只能跳一次的溢出题不会算、seccomp 沙箱题看不清放行了哪些 syscall。其中 one_gadget / seccomp-tools 其实早就在镜像里（A 档前的层装的），本次是**确认 + 写进提示词**，不是新装。

## 3. 三个真坑（都踩了，都修了）

### 3.1 `apt install python3-scapy` 装了但用不了
第一次构建直接红在自检 `import scapy` → `ModuleNotFoundError: No module named 'scapy'`。

根因：本镜像的 `python3` 是 **`/opt/venv` 里的解释器**，而 apt 的 `python3-scapy` 装进的是**系统 python3 的 `dist-packages`**，两者 site-packages 不互通。

修法：改走 `pip install scapy`（纯 Python，3.14 上可装）。Dockerfile 里留了注释，防止以后有人"优化"回 apt。

### 3.2 `pip install RsaCtfTool` 根本装不上
PyPI 上只有 1.0 / 1.1，`Requires-Python: >=3.8,<3.9`，而镜像里是 Python 3.14。

修法：vendor 源码（`vendor/RsaCtfTool/`，4.7 MB / 124 文件，去掉 .git/.venv/tests/docs），`pip install --no-cache-dir --no-deps /opt/RsaCtfTool`，依赖单独 pip 装（cryptography / urllib3 / requests / gmpy2 / pycryptodome / tqdm / z3-solver / psutil / factordb-pycli）。**不能带 `--no-deps` 之外的偷懒写法**——上游依赖表里有 `pycryptodomex` 等重包，全解会拖进一堆不需要的东西。

### 3.3 容器里不能装东西（两个原因叠加）
- 运行用户是 `solver`(uid 1000) → `apt-get`/`pip` 一律 Permission denied；
- 运行期 `--network none` → 就算有权限也下不到包。

所以所有安装**必须写在 Dockerfile 里、以 `USER root` 跑**，运行期只做"用"。这一条也是为什么 `pip install androguard` 在容器里永远失败（`SSLError(SSL_EOF_WHILE_READING)`）。

## 7. 追加：`suvex-sandbox-re`（逆向镜像）已重建

用户说「重建」后做的。

### 7.1 又一个同一个坑：pip 没给 `--index-url`
第一次构建直接断在 `pip install angr`：

```
#6 44.37 Could not fetch URL https://pypi.org/simple/angr/: There was a problem
          confirming the ssl certificate: [SSL: UNEXPECTED_EOF_WHILE_READING]
#6 44.39 ERROR: No matching distribution found for angr
```

根因：**re 的 Dockerfile 里 `pip install` 没有 `--index-url`**，而镜像里也没有全局 pip 配置 → 直奔 pypi.org，而构建期到 pypi.org 是 SSL EOF。base 镜像里早就用
`ARG PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple` +
`pip install --index-url "$PIP_INDEX_URL"` 解决过（base Dockerfile 第 657-673 行有整段说明），re 这份漏了。

修法：给 re 的 pip 段补同一个 ARG + `--index-url`（保持与 base 同一套写法，便于 `--build-arg` 换源）。补完 65 秒装完。
