# CTF 赛事自动托管（ctf_race）—— 学自 verialabs/ctf-agent

> 目标：把 verialabs/ctf-agent 的「整场比赛自动托管」成熟设计搬进 Suvex，
> 但**不照抄它关掉成本/止损闸的取舍**。多模型横向赛跑，与 Suvex 现有的
> `kernel/multiagent`（单题内纵向拆分 root+N child）正交叠加。

## 一、为什么做（它解决什么）

Suvex 原来的解题是「一道道手动点、单模型跑」。两个痛点：

1. **单模型卡死 = 整题失败**。一个模型走进死胡同就整题废。
2. **整场要人守着**。60 分钟长任务、几十道题，人工一题题点不现实。

ctf-agent 的答案是：**同一道题开多个模型并行赛跑，谁先拿到 flag 谁赢、
其余取消**；卡住就用兄弟的中间发现救回去重试；整场由 coordinator 自动
发现新题、跳过已解、排队并发。

## 二、六大搬来的设计（源码在 `app/ctf_race/`）

| 设计 | 文件 | 干什么 |
| --- | --- | --- |
| 多模型赛跑 | `swarm.py` | `asyncio.wait(FIRST_COMPLETED)`，首胜 `cancel_event.set()` 取消其余；bump 循环（gave_up/error→喂兄弟洞察重跑，冷却 `min(bump*30,300)`s，`max_bumps` 上限，broken 不 bump，连续 error 弃） |
| 兄弟消息总线 | `message_bus.py` | append-only findings（`MAX_FINDINGS=200`）+ per-model cursor，`post/check/broadcast/format_unread` |
| 重复动作检测 | `loop_detect.py` | 签名 `tool:json(args)[:500]` 的 deque(window=12)；≥3 warn、≥5 break |
| 成本追踪 | `cost_tracker.py` | `DEFAULT_PRICING` 按 1M token 计价（**不依赖 genai-prices**），`format_usage` + 总预算闸 |
| 整场编排 | `coordinator.py` | `MatchCoordinator.run_until_idle()`：poll→预算闸→开题到并发上限→reap→终止判定；平台已解/未开放跳过；失败重排 |
| 真实工厂 | `competition_racer.py` | 把 `competition.list_tasks/submit` + `build_spec` + `SandboxContainer` + `solve_in_sandbox` 接到 coordinator 的回调上 |

**关键区别（为什么正交不是重建）**：
- `multiagent` = 单题内纵向拆分（侦察/验证）。
- `ctf_race` = 多模型打同一题横向冗余赛跑。
- 二者可叠加：一个赛跑里的每个 solver 仍可开 `multiagent`。

## 三、接口与前端

后端（`app/ctf_race/router.py`，挂在 `/api/v1/ctf-race`）：

| 方法 | 路径 | scope |
| --- | --- | --- |
| POST | `/ctf-race/start` | scan（对外发包、起容器、烧额度） |
| POST | `/ctf-race/stop` | scan |
| GET | `/ctf-race/status` | read |

同一时刻只允许一场（进程内单例，重复 start → 409 `RACE_ALREADY_RUNNING`）。

前端（`suvex-web/src/components/kernel/RacePanel.tsx` + `data/ctf-race.ts`）：
- 未跑：起跑表单（模型清单 / 并发 / 预算上限 / 开始）。
- 跑起来：2s 轮询进度（只在 running 时轮询，不跑时零请求）、按题 stage
  的进度表、flag 落到已解题、失败备注、累计成本。
- 「请求停止」后按钮禁用并换文案「正在停止…」+ 红条提示「当前 step 跑完
  才收手，不用再点」—— 因为后端无法从半路掐断正在跑的 `run_shell`。

## 四、刻意**不**照抄 ctf-agent 的三处

1. **ctf-agent**：`Coordinator prompt` 写「NEVER kill a swarm」「Cost is not
   a concern」—— 等于关掉成本/止损闸。**Suvex**：`max_bumps` 上限 + 总预算
   闸（`max_budget_usd`）+ 达上限即 `stopped_reason`。
2. **ctf-agent**：Claude SDK solver 是 bash-only、无具名 `submit_flag` → trace
   实测模型在 bash 里瞎猜命令、满世界 `find`。**Suvex**：`submit` 是具名
   `competition.submit`，且 `accepted=False`（限流）不扣错误次数。
3. **ctf-agent**：竞态式收场（不设确定性上限）。**Suvex**：每层写单测 +
   保留确定性收场（`run_until_idle` 有 `max_rounds`、budget 闸、stop 事件）。

`docker/suvex-sandbox/Dockerfile`（Kali base），大部分工具已有（angr/unicorn/
capstone/pwntools/sagemath/volatility3/radare2/binwalk/…）。经**假设审计**

轮子且旧，fpylll+sympy 覆盖）、stegseek（C++ 二进制非 pip，已有 stegoveritas+
zsteg）、pyghidra（需整套 Ghidra+JDK，radare2/angr 已覆盖）、cado-nfs（无 apt 包）。
