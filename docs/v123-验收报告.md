# v1.23 验收报告：跑过工具的轮次独立纠偏额度 + 错误条真因/重试

## 用户报的两个现象

1. **「还是会自己中断啊」**（截图：对话停在 `Let me see the rest of the main function.`）
2. **错误条只写「请求失败，请稍后再试。」**，没有任何可据此行动的信息。

## 根因（都有数据）

### ① 纠偏额度被「空回复」吃光

线上会话 `chat_01M61DWC71W8989RRMW6DZS9SP`（33 条消息）的 `chat_turn_runs`：

```
status=done  round_index=4  nudges_used=2  truncations_used=0  tools_used=2
```

`nudge.should_nudge` 的判据顺序是 `nudges_used >= max_nudges → return False`
排在 `tools_used > 0` **之前**。而两次额度里有一次是**空回复**（`seq 18`
内容长度 0，模型抽风写了个空串）用掉的。于是轮到「刚跑完反汇编、只写了一句
`Let me see the rest of the main function.`」时，最硬的结构信号
（`tools_used > 0`）根本没机会生效 —— 界面停在那句英文上。

### ② 错误条丢掉了真因

store 把 SSE `error` 帧的 `detail` 塞进 `{ message: detail } as ApiError`。
类型断言 ≠ 实例；`ChatPage` 渲染走 `errorMessage(error)`，第一步是
`error instanceof ApiError` → 假 → 落到泛化兜底。

## 修法

### 对齐 CyberStrikeAI 的「多层各自独立额度」

参考（Apache-2.0，只学设计）：
- `internal/handler/finalization_auto_continue.go`：缺证据续跑独立额度 2 次、退避 500ms/1s/2s
- `internal/handler/eino_empty_response_continue.go`：空正文续跑独立额度 5 次、指数退避
- `internal/multiagent/eino_empty_response.go`：`IsEinoEmptyResponseResult` 只认占位语（空串不算）

我方落地：
- `suvex-api/app/chat/nudge.py`：判据顺序改为 `truncated → tools_used → nudges_used`；
  新增 `tool_nudges_used / max_tool_nudges` 参数。
- `suvex-api/app/chat/engine.py`：新增 `MAX_TOOL_NUDGES = 8`，两个循环各维护
  `tool_nudges_used` 计数（与截断计数互斥），并接进 heartbeat。
- `suvex-api/app/chat/models.py` + 迁移 `f7a2d5c91b36`：`chat_turn_runs.tool_nudges_used`
  （接手时接着用同一额度，否则每次自动接手都重置 = 无限续）。
- `suvex-web/src/data/chat.ts`：error 帧造**真** `ApiError`；`humanizeDetail` 剥掉
  `XxxError:` 前缀；`resumeTurn` 进入即清旧错。
- `suvex-web/src/pages/ChatPage.tsx`：错误条加 `data-error-code` 与「重试」按钮
  （指向最近一条 `status=failed` 的 run，走 `/turns/{id}/resume`，不重复发用户消息）。
