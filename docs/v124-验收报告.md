# v1.24 验收报告：插话只对「当前会话正在跑的那一轮」生效

## 用户报的现象

截图：新会话里出现「插话 · 模型下一轮会看到 / 你好」，同时底部一直挂着
「第 1 轮 · 模型在推理…」，不再变化。用户原话：**「一直再推理」**。

## 真因（数据库 + 服务端日志实证）

会话 `chat_01M61HVW8H0MRV14250F2JBK37`：

```
seq 1  user  2 字节  "你好"        ← 唯一一条消息
chat_turn_runs: 该会话 0 行
journalctl:     POST .../interject  200 OK   （从来没有 POST .../messages/stream）
```

即：**另一个会话**的长任务正在跑（78 秒），全局 `sending` 为 true →
用户切到新建会话打「你好」按 Enter → 前端判定"跑着 ⇒ 这是插话" →
走 `interject` → 服务端当时**不判有没有在跑**，直接落库并 200。
而那条消息所在的会话没有任何在跑的轮次会去读历史 ⇒ 永远没有回复。

两条独立的错：
1. 前端把「全局 sending」当成「当前会话在跑」（跨会话串味）。
2. 服务端 `interject` 的 docstring 写着「没在跑就等价于发一条新消息」——
   这句话是错的：一条 user 消息本身不起一轮，只有 `run_turn` 会。

## 修法

1. `suvex-web/src/data/chat.ts`：`sending` 增配 `sendingSessionId`。
2. `suvex-web/src/pages/ChatPage.tsx`：派生 `sendingHere` / `sendingElsewhere`；
   只有 `sendingHere` 才是插话语义。跑在别的会话时按钮仍是「发送」且禁用，
   占位符写「另一个对话正在跑 —— 等它跑完再发」。
3. `suvex-api/app/chat/router.py`：`interject` 加闸 —— 该会话没有 open 的
   `turn_run` → `409 NO_RUNNING_TURN`，**不落库**。
4. 兜底：前端 `interject` 返回 `'ok' | 'no-turn' | 'failed'`；`no-turn` 时
   `clearStaleSending()` 清掉过期的 `sending` 再退回 `sendMessage` ——
   这是 done 帧丢失（服务端早跑完、前端以为还在跑）时的救命路径，
   保证用户那句话不会被静默吞掉。
