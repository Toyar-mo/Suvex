# v1.27 验收报告：轮次上限对齐 CyberStrikeAI 的 800

## 用户诉求

「CyberStrikeAI 默认 800 我们也 800」

## 改动

| 常量 | v1.26 | v1.27 | 说明 |
|---|---|---|---|
| `MAX_TOOL_ROUNDS` | 200 | **800** | 与 CyberStrikeAI `max_iterations: 800` 一致 |
| `HISTORY_MESSAGE_LIMIT` | 200 | **400** | 随轮次同比放大 |
| `MAX_TOOL_NUDGES` | 100 | **300** | 否则它成为 800 轮下的新天花板 |

`MAX_HISTORY_CHARS` 保持 400k 字符（约 24 万 token，模型窗口 1M）——
**真正的成本闸是它**，不是条数。四个值都能用环境变量收紧：
`SUPEX_CHAT_MAX_TOOL_ROUNDS` / `SUPEX_CHAT_HISTORY_MESSAGE_LIMIT` /
`SUPEX_CHAT_MAX_TOOL_NUDGES` / `SUPEX_CHAT_MAX_HISTORY_CHARS`。

## 测试与部署

- 默认值断言提高（`>=800` / `>=200` / `>=200`），防止有人改回去。
- 全量后端 chat 套件 **285 passed**。
- Kali 部署后实读：`800 400 300`；`/api/v1/health` 200、前端 200。
