## 越权与注入强化手法

这一节只扩大**手法的覆盖面**,不改变任何判定纪律:上文第三节的禁令照旧成立
(不打字典爆破、不做压力测试、不碰真实凭证、不越出本题范围)。区别在于——
以前你可能试两三种手法就收工,现在要按下面的表把该试的试完再判。

下面全是"看到什么 → 做什么"的表。**照表走,不要自己发明流程**,也别跳步:
前一步没确认就做后一步,是这个流程里最烧回合的错法。

### 一、先把顺序定下来(任何入口都适用)

| 手上有什么 | 先做什么 | 为什么 |
| --- | --- | --- |
| 一个 HTTP 入口 | 把**所有**参数列全(query / body / header / cookie / path 段),标出哪些进了数据库、哪些进了文件系统、哪些拼进了命令 | 注入点取决于数据流向,不取决于参数名。叫 `id` 的完全可能是文件名 |
| 一组接口 | 按"能不能改数据 / 能不能读别人的数据"两类过一遍,先打读写交界处 | 越权几乎总落在"我的操作 + 别人的对象"这个组合上 |
| 一个报错 | 先看**报错全文与响应头**,不要只看状态码 | 500 的栈会直接告诉你是哪一层出的错(模板引擎 / ORM / 反序列化) |
| 一个打不动的点 | 先换**编码层**(URL 双编码 / Unicode / 大小写 / 分号截断),再换手法 | 大多数"打不动"是过滤器认得出原形、认不出变体 |

优先级:**一步内能确认的排前面**(回显型 > 报错型 > 布尔盲 > 时间盲)。盲注放最后,
它吃回合数,失败时的信息量也最低。

### 二、注入

#### 1. 先认出后端是什么(这一步错了,后面全白费)

用**只在一个引擎上能解析**的恒真式当指纹:跑通说明是它,报语法错说明不是。
一次发一组,把响应差异记下来。

| 怀疑是 | 指纹(恒真式) |
| --- | --- |
| MySQL | `conv('a',16,2)=conv('a',16,2)` / `connection_id()=connection_id()` / `crc32('MySQL')=crc32('MySQL')` |
| PostgreSQL | `5::int=5` / `pg_client_encoding()=pg_client_encoding()` / `current_database()=current_database()` |
| MSSQL | `BINARY_CHECKSUM(123)=BINARY_CHECKSUM(123)` / `@@CONNECTIONS>0` |
| Oracle | `ROWNUM=ROWNUM` / `RAWTOHEX('AB')=RAWTOHEX('AB')` |
| SQLite | `sqlite_version()=sqlite_version()` / `last_insert_rowid()=last_insert_rowid()` |

CTF 题里 SQLite 与 MySQL 占绝大多数,**先试这两个**。认错引擎会一直失败,而且
失败的样子看着像"注入被挡了"——那是假线索,会让你在原方向上白烧回合。

#### 2. 你手上有什么反馈,决定走哪条路

| 观测 | 走哪条 |
| --- | --- |
| 查询结果能回显在页面上 | `UNION SELECT`。先探列数(`ORDER BY N` 递增到报错),再对回显位 |
| 只有报错信息回显 | 报错注入:让错误信息里带出数据 |
| 只有"正常 / 异常"两种页面 | 布尔盲:构造恒真与恒假两条做差分 |
| 只有响应时间变化 | 时间盲:`sleep` / `pg_sleep` / `WAITFOR DELAY`。**先量一次基线**,否则分不出网络抖动 |
| 什么都没有 | 带外(让数据库去请求你能看到的地方)。做不到就写 `ruled_out` 并说明覆盖不到 |

#### 3. 过滤器在挡的时候,按这个顺序换形

| 挡住了什么 | 换成什么 |
| --- | --- |
| 空格 | `%09`(tab) `%0A` `%0B` `%0C` `%0D` `%A0`;`/**/` 内联注释;括号 `(1)and(1)=(1)`。**各库认的空白字符不同**:SQLite3 / PostgreSQL 只认 `09 0A 0C 0D 20`,MySQL5 还认 `0B A0` |
| 逗号 | `LIMIT 1 OFFSET 0` 代替 `LIMIT 0,1`;`SUBSTR(x FROM 1 FOR 1)`;多列用 JOIN 拼:`UNION SELECT * FROM (SELECT 1)a JOIN (SELECT 2)b` |
| 等号 | `LIKE` / `IN` / `NOT IN` / `BETWEEN`,如 `SUBSTRING(VERSION(),1,1)LIKE(5)` |
| 关键字 | 大小写混写(`aNd`)→ 同义函数(`SUBSTR`↔`MID`、`VERSION()`↔`@@version`)→ 内联注释拆字(`UN/**/ION`)→ 改注入位置(`ORDER BY` / `LIMIT` / `HAVING`) |
| 整条被拦 | 先确认拦的是**哪个字符**:逐字符删一个发一次,找到触发位再针对性编码。不要盲改 |

**不要**上来就挂 `sqlmap` 全自动扫:它的默认 payload 是最容易被挡的那一批,而且你看不到
它试了什么。手工确认有注入、拿到列数与回显位之后,再考虑让它跑。

#### 4. 模板注入(SSTI):先认引擎,再谈利用

先发一个覆盖多引擎的 polyglot:`${{<%[%'"}}%\.`,看报错指向哪一家。再用无害算式确认:
`{{7*7}}`(Jinja2 / Twig / Nunjucks)、`${7*7}`(FreeMarker / JSP EL)、`#{7*7}`(Thymeleaf / Ruby)、
`<%= 7*7 %>`(ERB / ASP)。区分 Jinja2 与 Twig:`{{7*'7'}}` 回 `7777777` 是 Jinja2,回 `49` 是 Twig。

| 观测 | 动作 |
| --- | --- |
| 求值结果直接显示 | 回显型:直接读 `config` / 环境变量 / 文件 |
| 只有报错 | 报错型:让表达式抛错,把数据塞进错误信息 |
| 只有真假两种响应 | 布尔盲,用**成对的**表达式:一对里一个正常求值、一个故意语法错,至少两对,避免外部干扰误报 |
| 只有延迟 | 时间盲 |
| 都没有 | 带外 |

模板常出现在**生成 PDF、发票、邮件**的功能里——这些地方最容易被漏掉。

#### 5. 命令注入:分隔符矩阵一次发全

分隔符:`;` `|` `||` `&` `&&` 反引号 `$()` 换行(`%0a`)。一次发一组,
不要一个一个试——在第 3 个上打中却以为前面都没中,是最常见的时间浪费。

| 挡住了什么 | 换成什么 |
| --- | --- |
| 空格 | `${IFS}`(`cat${IFS}/etc/passwd`)、花括号展开(`{cat,/etc/passwd}`)、输入重定向(`cat</etc/passwd`)、tab `%09` |
| 斜杠与反斜杠 | `${HOME:0:1}` 造 `/`、`$(echo . \| tr '!-0' '"-1')` 造 `/` |
| 关键字 | 十六进制:`$'\x2f\x65\x74\x63'`、`echo -e "\x2f..."`、`xxd -r -p`。大小写混写。反斜杠换行拆词(`cat /et\` + 换行 + `c/pa\` + 换行 + `sswd`) |
| `cat`、`ls` 这类被挡 | 通配符:`/???/??ss??`、`{l,-lh}s` |
| 没有回显 | 先时间侧信道确认存在(`;sleep 5`),再改外带:DNS 查询、请求你能看到的地址(仅本题允许时)、或写文件到可读路径再读 |

### 三、越权与认证

| 观测 | 动作 |
| --- | --- |
| 有对象 ID(数字 / UUID / 哈希 / 组合键) | 换成**别人**的 ID 再发一次。403 是拦住了;200 且返回别人的数据才是命中;200 但数据被悄悄换成你自己的,说明服务端以会话为准,换别处 |
| 界面上的按钮或菜单按身份隐藏 | 别只看界面。从 JS、前端路由、接口文档、`robots.txt` 里把接口清单捞出来,直接打 |
| 请求头里有 `Authorization: Bearer xxx.yyy.zzz` | 见下面 JWT 那张表 |
| `user_id` / `role` / `is_admin` 出现在你可控的位置 | 改一个试。服务端若以它为准,就是垂直越权 |
| cookie / session 看起来可猜 | 依次查:退出后是否真失效、是否可固定、是否可预测 |

JWT 单独看 header:

| header 里看到什么 | 试什么 |
| --- | --- |
| `alg` 由服务端决定,你改不动 | 先解出 payload,改声明(角色 / 用户 ID),签名不动,看服务端到底验不验 |
| `alg` 的候选里有 `none` | 改 `alg: none`,删掉签名段(保留末尾那个点) |
| 站点公开了公钥 | RS256→HS256 密钥混淆:把公钥当 HMAC 密钥重签 |
| 有 `jwk` / `jku` / `kid` | 三个都是注入面:`jku` 指向你自己的 JWKS;`kid` 试路径穿越或 SQL |
| 密钥像人设的短词 | 在**本地**对 token 验签来试(不发请求给靶站),这类离线爆破是允许的,但掩码要小、字典要小。**打登录口跑字典仍然禁止**(见上文第三节),两者不是一回事 |

**默认凭证**:产品默认账号(`admin/admin` 这类)单点试一次是正常检查,与"跑字典"是两件事。
次数要少,不要用字典文件。

### 四、文件与路径

路径穿越按编码层递进,**一次发全**,不要一次只改一层:

| 层 | 写法 |
| --- | --- |
| 原形 | `../` `..\` `..\/` |
| 单次 URL 编码 | `%2e%2e%2f` `.%2e/` `..%5c` |
| 双次编码 | `%252e%252e%252f`(服务端会解两次才生效) |
| Unicode / 超长 UTF-8 | `%c0%ae%c0%ae%c0%af` `%uff0e%uff0e%u2215` |
| 变形 | `....//`、`..;/`、`%00` 截断、绝对路径 `/etc/passwd`、Windows `C:\` |

读到内容才算命中。只报不同错误也是线索——它告诉你过滤器在哪一层。

**文件上传**四层依次试:后缀(`.php` `.phtml` `.php5` `.phar`、大小写、双后缀、
`shell.php;.jpg`)→ `Content-Type` → 文件头魔数(前面加 `GIF89a`)→ `.htaccess` 能不能传。

**LFI → RCE**:能包含本地文件后依次试——日志投毒(把代码写进 `User-Agent`,再包含 access log)、
`/proc/self/environ`、session 文件、`php://filter` 链、临时上传文件。

### 五、服务端请求类

| 观测 | 动作 |
| --- | --- |
| 参数像 URL / 域名 / IP | SSRF:先打你自己能看到的地址,确认请求真发出去了;再试协议 `file://` `gopher://` `dict://`;再试云元数据 `169.254.169.254`。被挡时换十进制 IP、八进制、`[::]`、DNS 重绑定 |
| 请求体是 XML | XXE:先试回显型(读 `/etc/passwd`),不行转盲 XXE 走外部 DTD 外带。解析器默认禁外部实体时会直接报错告诉你 |
| 数据里有序列化魔数 | 反序列化:Java `rO0AB` / `aced0005`、PHP `O:数字:"类名"`、Python pickle `\x80\x04`。**先认出语言,再找 gadget**,顺序反了就是白试 |

### 六、竞态

只在"检查与使用之间有窗口"的地方试:余额扣减、优惠券、上传后校验、唯一性检查。
5–10 个并发就够,**不要**加压测级别的并发——那既触发滥用检测,也说明不了更多。

### 七、什么时候收手

- 一条手法试完三种变体没反应,换手法。不要在同一条上无限变形。
- 每条手法都**记下试过什么**(具体 payload + 响应摘要)。这既是证据,也是下一轮不重复的凭据。
- 确认打不动就写进 `ruled_out`,附上试过哪些变体、观察到什么、覆盖到什么程度。
  只写"试过了不行"等于没写——判断依据要能被别人复核。
