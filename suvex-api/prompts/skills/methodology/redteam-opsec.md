## 行动隐蔽与被封后的处置

> 打得进 ≠ 打得稳。被发现即行动归零。
> 每个动作执行前先问一句：这步在防守方眼里长什么样。

### 一、请求被拒（403 / 429 / 超时）时的处置顺序

被拦的第一反应**不是重试**，是换一个维度再试。逐条往下试，上一条无效才走下一条：

1. **看响应正文，不要只看状态码。** 很多 WAF 回 200 但正文写着"拦截"；
   也有回 403 但正文其实是应用自己的权限错误（那就是另外一条路了）。
2. **换客户端标识**：`User-Agent` 换成常见浏览器、补 `Referer` / `Accept-Language`。
   缺 UA 的请求在多数 WAF 里直接判机器。
3. **试转发头**：`X-Forwarded-For` / `X-Real-IP` / `CF-Connecting-IP` / `True-Client-IP`，
   各试一次。**只有一种写法有效时说明这条链路信任该头**，之后所有请求都带上它。
   ⚠️ 这是**绕过应用层黑名单**的手法，不是隐藏真实来源 —— 它的用途是让靶机认为
   你来自另一个地址。不要用它去打授权范围外的任何东西。
4. **降速再试**：连续命中 429 时先降到 1 req/s 以下，确认是不是纯粹的速度问题。
5. **换路径写法**：`/admin` → `/admin/` → `/./admin` → `//admin` → `/admin%2f`，
   有些规则只看字面前缀。
6. **换入口**：同一套逻辑可能还有别的路由/参数/子域在跑（这本来就是侦察该产出的东西）。

### 二、速率与时序：别把自己打出去

| 场景 | 该做的 | 为什么 |
| --- | --- | --- |
| 端口/目录扫描 | `nmap -T2`、`ffuf -p 0.1`（每请求间隔）、`--max-rate` 限速 | 全速扫描是**最容易**触发 IDS 阈值与自动封禁的动作 |
| 爆破类（`hydra` / `john` / `hashcat` 对在线服务） | 先算密钥空间再决定要不要跑 | 在线爆破几小时没结果时，账号通常已经锁了 |
| 高危验证（命令执行、写文件） | 低频、单次、非破坏 | 验证一次就够；重复打只会留下更多痕迹 |
| 时间选择 | 避开业务高峰，也避开深夜 | 贴合目标作息的动作最不显眼 |

### 三、最小足迹

- **优先只读**：能读到的东西不要靠写来验证。
- **内存执行优先于落盘**：临时文件放 `/dev/shm`（内存盘），别留在 `/work` 之外。
  我们的沙箱是 `--read-only`，可写位置只有 `/work`。
- **用完即删**：自己上传/生成的东西，验证完删掉。
- **别动监控与审计**：停掉日志服务本身就是最强的告警信号。
  在 CTF 靶机上也没必要 —— 你不是来清理痕迹的。

### 四、⚠️ 我们的沙箱有一条硬限制，先看清再动手

`crypto` / `取证` / `逆向` 类题的容器是 **`--network none`**：容器里**没有任何网络**。

    真正的人不会先怀疑"是不是没网"，会先怀疑目标 —— 于是把
    `Network is unreachable` 读成"目标不可达"，换目标再试，一路烧回合。

所以：

- 只有 **web / pwn / 网络类** 题才有出网能力（且出网仍受 iptables 白名单限制）。
- 在无网容器里，`proxy` / `--socks5` / Tor 这条路线**完全不存在**，不要写进命令。
- 判断当前容器有没有网，一条命令就够：`curl -s -m 5 -o /dev/null -w '%{http_code}' <靶机URL>`
  回 `000` = 不通（或超时），回 `200/302/403` = 通。

### 五、红色的那条线

隐蔽不等于越界。以下在**任何**情况下都不做（这也是平台侧的白名单与 `guard_tool_url`
会直接拒掉的）：

- 对授权范围外的地址发请求（换头、换代理都不改变这条判据）。
- 拒绝服务型压测（高并发、资源耗尽）。
- 在目标上植入持久化后门、反弹 shell、计划任务。
- 批量下载/篡改目标数据。

> 隐蔽是「别让正常动作把自己打出去」，不是「让自己可以为所欲为」。
